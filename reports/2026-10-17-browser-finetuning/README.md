# 浏览器动作选择：完整 GPU 微调实验

2026-10-17，在原实验 EC2 `i-0daca64f56056aa1c`（g6.xlarge / NVIDIA L4）上，
通过统一入口 `finetune.py`，从原始 Strands Decider v19 完成一轮浏览器动作选择微调。
**独立测试准确率从 53% 提升到 100%，全部流程检查与预设质量门槛通过，退出码 0。**

这是合成页面状态上的离线 choice 判断，没有打开真实网站或执行点击。
场景参考 Jev 的浏览器控件选择任务；数据沿用此前的
[场景筛选实验](../2026-10-17-scenario-screening/README.md)，不是对 Jev 原仓库成绩的复现。

## 独立测试结果

每题从 8 个控件及刷新、等待、阻塞中选择一个动作，共 11 个选项。
优先刷新过期快照，其次等待加载完成，再选择当前面板内满足订单、文档、语言、
可见性、可用性及只读要求的唯一控件；不存在合法控件时选择阻塞。

| 指标 | 原始 v19 | 微调版 |
| --- | ---: | ---: |
| 测试准确率 | 53%（106/200） | **100%（200/200）** |
| 候选反序并改名后的准确率 | 49.5%（99/200） | **100%（200/200）** |
| 实际选择一致率 | 73.5%（147/200） | **100%（200/200）** |
| 平均 NLL | 2.099809 | 0.005225 |
| 四类动作的宏平均准确率 | 25.21% | 100% |

下面的点击成绩要求选中正确控件，仅选择了“点击”类别并不算正确。

| 正确动作类别 | 测试题数 | 原版答对 | 微调答对 |
| --- | ---: | ---: | ---: |
| 点击匹配控件 | 120 | 103 | 120 |
| 刷新过期快照 | 40 | 0 | 40 |
| 等待加载完成 | 20 | 0 | 20 |
| 没有合法控件，阻塞 | 20 | 3 | 20 |

80 道应刷新、等待或阻塞的题中，原版 **66 次仍预测点击**，微调版为 **0 次**。
原版共 83 次点击选择违反至少一条规则，包括旧快照、加载中、错误订单/语言/文档、
错误面板、禁用控件及非只读动作；微调版为 0 次。
其中 15 次原版选择指向 `pay` 控件，均为离线预测，没有执行支付操作。
违规原因可以重叠，不能把各原因次数相加当成错误题数。

逐题比较共修正 94 道原版错误，没有把原本正确的题改错。
完整混淆矩阵、重叠违规统计见 [diagnostics.json](diagnostics.json)；
全部 200 题的原始状态、前后动作和规则核对见 [test-comparison.jsonl.gz](test-comparison.jsonl.gz)。
两版原始逐题记录还保留候选换序后的选择。

## 实际修正案例

题号为测试文件中的零起算行号。

- `row=6`：观察版本 4644，当前版本 4645。原版判“没有合法控件”，微调版正确选择刷新。
- `row=8`：页面版本一致，但 `loading=true`。原版判阻塞，微调版正确选择等待。
- `row=9`：需要英文 invoice，原版点击德文 invoice 控件 `e301`；微调版正确判为没有合法控件。
- `row=22`：需要订单 `order-3784` 在 preview 面板中的英文 shipping label。
  原版选择 orders 面板、订单为 `order-3784-other` 的 `e378`，微调版正确选择 `e925`。

## 数据与训练

实际数据保存在 [browser_controls](../2026-10-17-scenario-screening/data/browser_controls)：
train 1,600 条；validation、calibration、test 各 200 条。
另外 160 条 discovery 只用于之前的场景筛选，没有进入本轮四个分区。
五份数据共 2,360 条，全部重新计算规则标签；状态和分组的跨分区检查通过。
四份实际 GPU 输入也与归档源数据规范化后的内容逐条相同。
见 [标签及来源核对](source-verification.json)和[入口数据审计](data-audit.json)。

| 项目 | 配置或结果 |
| --- | --- |
| 起点 / 基座 | 原始 Strands Decider v19 / Qwen3.5-2B-Base |
| 更新范围 | 原有 LoRA 和 pointer head；基座冻结 |
| 可训练参数 | LoRA 16,819,200；head 1,053,184 |
| epoch / 优化步数 | 1 / 100 |
| microbatch / 梯度累积 | 2 / 8，有效 batch 16 |
| LoRA / head 学习率 | `2e-5` / `1e-4` |
| 随机种子 | 20261017 |
| 最长训练/验证输入 | 1,021 token，无截断 |
| 原版验证准确率 | 51.5% |
| 第 50 / 100 步验证准确率 | 100% / 100% |
| 选中检查点 | 第 50 步；准确率持平时保留先达到者 |
| 独立校准温度 | 2.1134892，使用 200 条 calibration |
| 训练循环时间 | 993.38 秒，约 16.6 分钟 |
| 完整入口任务时间 | 1,292.66 秒，约 21.5 分钟 |
| PyTorch 峰值 allocated 显存 | 约 4.50 GiB |

检查点仅依据验证准确率选择，没有根据测试成绩调参。
两次验证准确率相同，第 100 步的验证 NLL 更低，但 NLL 不属于本次检查点选择标准。
训练前的 LoRA/head 散列与筛选实验中的原版 v19 一致，训练后两者均发生更新。
环境为 torch 2.7.1+cu126、transformers 5.17.0、peft 0.21.0、tokenizers 0.23.2。

## 模型与复现

本机最终校准检查点：

```text
artifacts/scenario-finetuning/browser_controls/download/pipeline/eval-v1/adapted/calibrated/
```

完整私有备份：

```text
s3://strands-decider-tetris-training-632930644527/browser-sft-20261017-020045/results/
```

仍需原始基座。当前检查点引用 `/opt/models/base`，迁移时按
[检查点加载说明](../../finetuning/README.md#使用产出的检查点)调整副本中的路径。
原版、验证最佳模型、最后一步模型及日志都保存在完整运行目录中。

用相同数据通过统一入口重新训练：

```bash
cp examples/scenario-finetune.json my-browser.json
# 设置原始 v19 的 model.checkpoint 和基座的 model.base_model。
uv run python finetune.py \
  --data reports/2026-10-17-scenario-screening/data/browser_controls \
  --config my-browser.json \
  --output artifacts/runs/browser-repeat
```

本次远端复用了已有环境，`runtime.auto_setup=false`，没有重新验证 CUDA 自动安装路径。
实际配置见 [config.json](config.json)。

这 200 道测试题来自独立种子和状态，但与训练集共享生成模板。
100% 只说明该合成分布上的结果，不证明真实网页、任意 DOM 或实际浏览器执行的成功率。
真实接入前应加入目标网站的状态与动作记录，并由宿主执行快照、可见性和权限等硬约束检查。
